02 · 拆开看 / HOW IT WORKS

它到底在解决什么

工作计划表是树和现实之间的那道桥。一行至少四列：议题 / 假设、需要的分析、数据来源、负责人 + 期限 + 交付物。写不出「数据来源」那一行，说明这片叶子还查不动，得再切。

它最实际的作用是提前暴露缺口：三个人都以为对方会去数人流，表一填发现那格空着。这种事在会上靠口头确认几乎抓不到。

为什么管用

拆完之后如果没有「谁、查什么、什么时候交」，树就只是墙上的一张图。工作计划表把每片叶子变成有责任人的待办，让进度可以被核对而不是被感觉。

拆成三块逐块检查，缺哪块就补哪块
一行一个分析项行要小到半天能做完，别写「市场研究」这种大词。
数据源与口径写明用哪张表、哪个时间窗、按什么单位。
责任人与交付谁、何时交、交出来是什么形态（一张表 / 一段结论）。
03 · 三步上手 / DO IT

今天下午就能做的三件事

01

把保留下来的每片叶子抄成一行。

02

逐行填分析方法、数据来源、负责人、期限。

03

填不出来的格子当场再切小，或干脆剪掉。

什么时候用，什么时候别用
该用

多人协作、跨部门取数，或分析要跑超过一天时。

别用 / 换招

一个人半小时能做完的小问题，写表比做还慢。

别和「优先级剪枝 / 影响–可行性矩阵」搞混

剪枝决定「查哪些」，工作计划表决定「谁来查、什么时候交」。

04 · 举个真例子 / THE COFFEE STAND

周末咖啡摊，摊开来算一遍

EXAMPLE · 示意算例

叶子：「14–16 点路过人数」。计划表这一行写：分析＝定点计数两个下午；来源＝摊位前人行道，手动计数器；负责人＝小鱼；期限＝周三 18:00；交付物＝一张两列小表（时段 / 人数）。第二天早上开会，不用问「进展如何」，直接看那张表在不在。计划表把「进度」变成了「东西」。

一步一步推给你看用符号、句式或示意数字走一遍；涉及数字均为教学假设，不是调研数据
  1. ① 叶子转成行查两周下午客流 → 收银小票 → 周三一行只放一个可交付的东西
  2. ② 估工作量2 小时取数 + 1 小时核对 = 半天估不出来通常说明行切得太大
  3. ③ 反推排期周三拿到数 → 周四算完 → 周五给结论从截止日倒着排，而不是顺着拖

07 · 带走一句 / TAKEAWAY
“写不出数据来源的那一行，就是明天会卡住的那一行。”
做完该留下
  • 每行能回答「谁 / 查什么 / 用哪个数 / 何时交」
  • 没有「持续跟进」这类无交付物的行
  • 有一列写清「做完长什么样」

差距分析 As-Is / To-Be

GAP ANALYSIS

现在在哪、要去哪、中间缺的到底是什么？

把「现状」和「目标态」并排摆好，缺口才会具体到能派活。

02 · 拆开看 / HOW IT WORKS

它到底在解决什么

两张图并排：左边 As-Is（现在实际怎么跑，包括那些没人写进制度的 workaround），右边 To-Be（改完具体怎么跑）。中间那栏才是重点——逐项写「缺什么」：流程、工具、技能、还是决策权。

常见错误是把 To-Be 写成愿景（「高效协同」），或者把 As-Is 写成制度文档里规定的样子。两边都得写「实际发生的事」，否则缺口是假的。

03 · 三步上手 / DO IT

今天下午就能做的三件事

01

As-Is 写实际发生的步骤，含临时办法。

02

To-Be 写具体到「谁在什么时候做什么」。

03

逐行填缺口类型：流程 / 工具 / 技能 / 决策权，各配一个动作。

04 · 举个真例子 / THE COFFEE STAND

周末咖啡摊，摊开来算一遍

EXAMPLE · 示意算例

As-Is：订单记在纸巾上 → 谁看见谁做 → 忙起来漏。To-Be：接单即填共享表 → 表上自动带负责人 → 每日收摊前对一次。缺口栏一填，发现不是缺人、也不是缺培训，而是缺一张所有人都看得见的表和「谁填」这条决策权。于是两个小动作就补齐了，不必重做整套流程。

05 · 常见翻车 / WATCH OUT

最容易摔的这三跤

01

别这样

As-Is 抄制度文档，写的是「应该怎样」而非实际，缺口全是假的。

02

别这样

To-Be 写成「提升效率」这类愿景，两边根本没法比。

03

别这样

缺口不分类型，一律归成「加强管理」，于是只能开会。

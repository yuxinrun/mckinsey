02 · 拆开看 / HOW IT WORKS

它到底在解决什么

是否树是三种逻辑树里最「 actionable」的一种：每个节点都是一个可以当场回答的是非题，每条路径末端必须落到一个动作，不能写「再观察」。它适合流程成熟、判断条件已知的场景，比如客服排障、报销审核、现场决策。

顺序有讲究：把最能分流、又最好判断的问题放在树根。如果第一个问题就要查三天数据，这棵树就白画了。

为什么管用

当选项只剩两三个，继续拆解就是浪费。是否树把判断压成一串是/否，每个岔口对应一个能查到的事实，于是争论从「我觉得」变成「去查这个数」。

拆成三块逐块检查，缺哪块就补哪块
一串二选一每个岔口必须能用是或否回答。
岔口绑一个事实「够不够」这类模糊判断要先换成可核的数。
每条路径落到动作不能出现走到叶子却不知道该干嘛。
03 · 三步上手 / DO IT

今天下午就能做的三件事

01

把最关键、最好判断的那个是非题放在树根。

02

每个分叉给两个互斥出口，不留中间态。

03

每条路径末端写一个动作，动词开头。

什么时候用，什么时候别用
该用

选项清楚、判定条件明确，需要快速给出「做 / 不做」时。

别用 / 换招

条件本身模糊或互相纠缠（比如「品牌感够不够」）时，二叉树会假装精确。

别和「议题树」搞混

议题树用来展开未知，是否树用来在已知选项之间收敛。

04 · 举个真例子 / THE COFFEE STAND

周末咖啡摊，摊开来算一遍

EXAMPLE · 示意算例

咖啡摊早上的树：「昨天剩下的豆子还够今天用吗？」 够 → 「按常规量开门」；不够 → 「今天有配送吗？」 有 → 「先卖挂耳，等配送」；没有 → 「把今日菜单改成只卖两种，并贴告示」。整棵树三个问题、四个动作，新员工看一遍就能照做，不用每次打电话问老板。

一步一步推给你看用符号、句式或示意数字走一遍；涉及数字均为教学假设，不是调研数据
  1. ① 第一个岔口多开 2 小时的增量毛利 > 0？先问最便宜、最能一票否决的
  2. ② 继续分叉是 → 再问「是否 ≥ 200 元」；否 → 不延每个岔口只加一个条件
  3. ③ 叶子绑动作≥200 → 延；0~200 → 先试一天再定不允许悬空路径
05 · 常见翻车 / WATCH OUT

最容易摔的这三跤

01

别这样

拿它去解完全没摸清的题：判断条件本身就是猜的，树越画越虚。

02

别这样

分叉写成「视情况而定」，等于把问题原样退回去。

03

别这样

末端写「进一步分析」，树就失去了它唯一的价值——给动作。
